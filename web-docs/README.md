# CoderWiki Docs статический портал документации

Собирает из папок, zip-архивов и `.xdp`-пакетов, скачанных из CoderWiki, многоязычный статический сайт на [VitePress](https://vitepress.dev): витрина репозиториев, поиск, Mermaid-диаграммы, переключение языков, SEO (canonical, OpenGraph, hreflang, sitemap).

## Быстрый старт

```bash
cd web-docs
yarn install
# положите в data/ папки или zip вида owner__repo@language-docs
yarn dev      # sync + предпросмотр на http://localhost:4173
yarn build    # sync + статический сайт в docs/.vitepress/dist
yarn preview  # посмотреть собранный сайт
```

## Данные

В `data/` (или в папке из `DOCS_SOURCE_DIR`) ожидаются:

- папки `owner__repo@language-docs/` с `_OVERVIEW.md` и главами `NN-….md`;
- **или** zip-архивы `owner__repo@language-docs.zip` с тем же содержимым (корень архива либо сами `.md`, либо одна папка с ними);
- **или** пакеты `.xdp` (экспорт CoderWiki Desktop, любое имя файла) из одного пакета разворачиваются **все** языковые версии, плюс список исходных файлов каждой главы (улучшает сопоставление глав и теги).

`.xdp` распаковывается встроенным zstd Node.js (нужен Node 24+ для пакетов со словарём). Если его нет используется CLI `xdp-util` (`XDP_UTIL_BIN`, либо `../xdp-rust/target/release/xdp-util`, либо из `PATH`).

Если есть и папка, и архив берётся более свежий по дате изменения. `language` полное английское имя языка, как в CoderWiki (`russian`, `english`, `chinese`, …).

Перед каждым `dev`/`build` скрипт `scripts/sync.mjs`:

1. очищает `docs/` от прошлых сгенерированных страниц (остаются `.vitepress`, `public`, `index.md`);
2. распаковывает архивы, транслитерирует имена файлов в URL-слаги, переписывает внутренние ссылки;
3. добавляет frontmatter (title, description, keywords, lang, служебные `cw*` поля);
4. пишет `docs/.vitepress/generated-manifest.json` единственный источник данных для меню, сайдбаров и витрины;
5. печатает отчёт: репозитории, языки, главы, битые ссылки.

## Настройки (`.env`)

| Переменная        | По умолчанию            | Назначение                                                       |
| ----------------- | ----------------------- | ---------------------------------------------------------------- |
| `DOCS_SOURCE_DIR` | `./data`                | Откуда брать документацию                                        |
| `SITE_URL`        | `http://localhost:4173` | Домен для canonical, OpenGraph, sitemap и robots                 |
| `BASE_PATH`       | `/`                     | `/` для своего домена, `/имя-репозитория/` для GitHub Pages      |
| `XDP_UTIL_BIN`    |                       | Путь к `xdp-util`, если встроенный zstd Node.js недоступен       |

## Структура URL

- `/` витрина (язык интерфейса: сохранённый выбор или язык браузера);
- `/ru/`, `/en/`, … та же витрина с интерфейсом на этом языке;
- `/<lang>/<owner>/<repo>/` обзор репозитория (`_OVERVIEW.md`);
- `/<lang>/<owner>/<repo>/<slug>` глава.

Бейджи языков в статье, переключатель языка и `hreflang` ведут на **ту же по смыслу** главу на другом языке. Сопоставление без ИИ, по общим признакам: упомянутые исходные файлы (и `files` из `.xdp`), идентификаторы из кода, узлы mermaid-диаграмм, относительная позиция главы. Сначала строится взаимно-однозначное соответствие, затем по номеру, затем ближайшая по смыслу глава; иначе обзор. Статистика печатается в отчёте sync.

## Теги

Теги репозитория вычисляются автоматически: языки по расширениям файлов (`.rs` → Rust, `Cargo.toml`, `package.json` …), технологии по упоминаниям в тексте всех языковых версий (Docker, PostgreSQL, P2P, Cryptography …), до 6 тегов. На витрине панель тегов и теги на карточках; фильтр по одному тегу за раз, выбранный тег сохраняется в `?tag=`.

## Публикация на GitHub Pages

Workflow `.github/workflows/web-docs-pages.yml` собирает и публикует сайт при пуше в `main`. В Settings → Secrets and variables → Actions → Variables задайте:

- `BASE_PATH` `/имя-репозитория/` (или `/` для домена `user.github.io` / своего домена);
- `SITE_URL` `https://user.github.io` или ваш домен.

В Settings → Pages выберите источник **GitHub Actions**.

## Ограничения

- Поиск VitePress индексирует страницы **текущего языка** (локали) это ограничение встроенного движка.
- Сопоставление глав эвристическое: главы без кода, путей и диаграмм сопоставляются по номеру.
